## The test

A source is **ALLOWED** only if all four hold:

1. **Commercial use permitted by explicit written licence term** — not by
   absence of prohibition, and not by "everyone does it".
2. **No share-alike or derived-database obligation** that would reach the model
   weights or the model's outputs.
3. **No field-of-use, research-only, or non-commercial restriction.**
4. **Any attribution obligation is satisfiable by an entry in the generated
   `NOTICE.md`.**

Everything else is **BLOCKED**, or **EVAL-ONLY** — usable for benchmarking,
never for training a commercial model.

That third category carries more weight than it sounds like it should. A large
share of published EO benchmark datasets are research-licensed. Citing your
score on one is legitimate; training on it is not. Both facts are true at once,
and a register that collapses them into "we use it" is the shape a licence
problem takes before anyone notices it.

## Why this is a hard gate rather than a register field

A model trained on data you cannot commercially exploit is a liability you have
paid GPU hours to create. Licence defects are the one class of defect that gets
*more* expensive to fix the longer you train, because the remedy is discarding
the weights, not patching them. That is why the licence check sits at T5 in
triage and again at R9 in correctness, and why R9 runs on every commit rather
than once a loop.

## Enforcement

`docs/allowlist.yaml` is the machine-readable allowlist. `mlkit` refuses to
validate a manifest containing a source absent from it, and R9 fails the build
in CI.

**The allowlist is signed by a human.** Adding an entry requires a human commit
carrying the licence URL and the retrieval date. An agent proposes additions in
`docs/ESCALATIONS.md` and may not edit `docs/allowlist.yaml` under any
circumstance. This has the same structure as S5 for the same reason: it is a
legal exposure decision, not a code change.

An allowlist that exists but is unsigned is a proposal. `mlkit` reports T5 and
R9 as ESCALATED against it — never PASS — so an unsigned file cannot be
mistaken for a determination.

## Verification protocol

Each entry is verified against the source's **own live licence page**, recorded
with the URL and the date it was read. Specifically:

- **Data sources** — the licence or terms page of the distributing authority,
  not a mirror's README and not a summary in a paper.
- **Model weights** — the licence file *in the model repository itself*. Not
  the paper, not the README, not a blog post. Licence variants within an
  otherwise permissive family are common, and the README is the field most
  likely to be out of date.

Licences change. "It was open when I looked" is only defensible if you recorded
when you looked, which is why `retrieval_date` is mandatory and `mlkit` rejects
an entry without one.

## Categories requiring explicit examination

The readiness package (r2) flags the following as traps — cases where the
obvious reading is wrong or incomplete. Each is listed here as **a question to
resolve during verification, not as a determination**. None of these has been
verified yet; see `docs/ESCALATIONS.md` for the live status of each.

| Source class | The question to answer |
|---|---|
| Copernicus Data Space portal contents | Sentinel scenes and derived portal products may carry different terms. Resolve per product, not per portal. |
| OpenStreetMap | Determine whether its share-alike and derived-database obligations reach model weights or outputs. |
| Overture Maps | Determine layer by layer which layers descend from OSM and inherit its terms. |
| PlanetScope | Determine whether any use here is training or citation. |
| HIFLD | Determine which tier each layer came from. Directly affects blackout. |
| Foundation-model checkpoints | Verify each checkpoint's own licence file individually. |
| Published EO benchmarks | Assume EVAL-ONLY until proven otherwise. |

## NOTICE.md

`NOTICE.md` is generated by `mlkit notice` from the allowlist's attribution
obligations. It is never hand-edited — an edit would let it drift from the
allowlist it is supposed to reflect, and R9 fails when it has. For a company
selling to banks and insurers, a generated attribution file is a due-diligence
deliverable, not housekeeping.
